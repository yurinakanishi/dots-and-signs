# 検証記録

2026-10-18、Windows、Node.js 24、Chromeの専用テストプロファイルで確認。

## この版の対象

数字の教材、学習記録、サイドメニュー、説明画面を削除し、こんにちは・こんばんは・ありがとうの単一練習画面に変更。公式教材の表現に合わせた模式図、手と顔・肩の位置を使った順序判定を追加。

その後、3段階の実判定と表示・お手本を同期。両手検出の本数表示、位置に基づく2つの手の追跡、短い欠落時の待機を追加した。以下はこの変更後の結果。

実モデルはHand LandmarkerとPose Landmarker Liteを同一Workerで起動し、空画像、pointing_up、victory、thumb_up、poseと、それぞれの反転を入力。手・体の正例を検出し、どの静止画像も3つのあいさつとして成功しなかった。推論時間の観測値はウォームアップを除き38〜73ms程度（この端末・検証画像のみ）。モデル本体の精度評価ではない。

ブラウザでは3教材の切り替え、お手本の静止、スマホ幅、実モデル起動後の権限拒否、合成骨格による3課題の成功、再試行、マイク非使用、停止・タブ非表示・許可待ちキャンセル後のカメラ解放を確認。未処理のページ例外はなし。MediaPipeのWASMログにはCPU delegateの初期化情報と通常の警告が出る。

合成骨格をWorker境界に入力するUIテストは、実カメラ映像のあいさつ認識を証明しない。テスト用の上書きは専用ブラウザ内だけで実施し、アプリにはテスト用経路を組み込んでいない。

静的ビルドでも両モデルの起動と空画像の推論を確認。モデル・WASM・フォントを含め34リクエストが同じ配信元で完結し、外部リクエスト・読み込み失敗はいずれも0。`npm run check`（43件のテストと本番ビルド）も成功。

## 進行表示・両手の検証

「こんにちは」のステップ1が成立するとチェックが付き、ステップ2が現在位置になり、お手本も両人差し指の形へ進むことを確認。片手だけの場合は1本検出・必要2本と表示し、両手の検出だけでは形の成立にせず、両指を立てた後にステップ3へ進む。両方を曲げるまで完成にしない。短い検出漏れで完了済みの段階を保ち、再試行・教材変更・停止で消えることを確認した。これは合成骨格による19項目のUI回帰テスト。

実モデルの追加9ケースは、片手、公式 `right_hands.jpg`、その反転、左右2本を大・中・小に配置した入力、再び片手→両手、空画像。各7フレームを入力し、最後の3フレームで期待する検出数と別々の追跡IDを確認。小サイズは高さ220pxの手を1280×720画像へ配置。初めの1〜2フレームだけ本数が不足したケースはある。公式の両手写真を模擬カメラ映像に流す実Workerの確認でも「手を2本検出」と2色の骨格を表示した。

もともと `numHands: 2` だった。検出しきい値0.7と公式標準の0.5を片手→公式両手画像で比較した範囲では、検出数は同じだった。左右ラベルの重複を理由に2本を拒否する不具合と、1フレームの欠落で進行が消える挙動を修正したが、「両手を離して映しても片手だけ」という利用者の実カメラ条件自体は再現できていない。調整済みしきい値だけで解決を保証しない。
