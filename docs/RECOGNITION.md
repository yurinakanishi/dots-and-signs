# あいさつの練習判定

調査・更新日: 2026-10-18（日本時間）。

## 対象

選んだ「こんにちは・こんばんは・ありがとう」の指定された手の動きを、PCカメラで順に確認する。自由な手話の認識・翻訳や、表情・文法を含む日本手話全体の評価ではない。数字の旧教材は削除した。

## 教材の根拠

- [秋田市「手話を覚えよう！」](https://www.city.akita.lg.jp/kurashi/shogaifukushi/1006373/1004961.html): 基本教材。こんにちはは額の2指から「あいさつ」、こんばんはは両手の交差から「あいさつ」、ありがとうは手の甲に当てた手を上げる。共通の「あいさつ」は両手の人差し指を近づけて曲げ、会釈する。資料は秋田県聴力障害者協会提供。左右どちらの手でもよいと説明されている。
- [奈良市「あいさつ編」](https://www.city.nara.lg.jp/soshiki/34/77111.html): ありがとうの直角の向き・小指側・会釈を照合。こんにちは・こんばんはの後半の表現には別の形があるため、このアプリの教え方に混在させない。
- [柏崎市「簡単な手話をやってみよう！」](https://www.city.kashiwazaki.lg.jp/soshikiichiran/fukushihokembu/fukushika/3/2/7/45170.html): ろうあ者福祉協会協力の動画。手話表現の地域・年代差が示されている。

公式の写真・動画は転載しない。独自の模式図を使い、原典へのリンクを示す。模式図だけで表現の正確さを保証しない。

## モデルの根拠

- [Google Hand Landmarker Web guide](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js): 手の21点とworld coordinatesを取得。左右判定スコアは手話の正しさを示す確率ではない。
- [Google Pose Landmarker Web guide](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js): 同じ画像から体の33点とvisibilityを取得。同期推論をWorkerに分け、画面操作を止めない。
- [Pose Landmarker models](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/index): Liteの固定バージョン1を使用。
- [Google公式の姿勢テスト](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/python/test/vision/pose_landmarker_test.py)と[手のテスト](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/python/test/vision/hand_landmarker_test.py): 実モデル起動確認の入力画像を選ぶために参照。

MediaPipeは手話分類器としては使っていない。骨格からこの3課題専用の幾何・時系列ルールを実行する。画像を汎用言語モデルへ送って正誤判定する方式は採用していない。

## 入力と品質条件

同じフレームをHand LandmarkerとPose Landmarkerに通す。手は最大2つ、体は1人。入力画像は非反転で、表示だけを鏡表示する。モデルの左右ラベルはGoogleの実画像と反転画像で確認しており、旧APIの左右入れ替え規則を流用しない。

モデル検出・presence・trackingしきい値は手0.5（Google公式の標準値）、体0.65。以前の手0.7は小さな手や2本目を落とす要因になり得るため変更した。ただし、公式画像で0.7と0.5を比較した範囲では検出数に差はなく、この変更だけで利用者の症状が解消したとの証拠はない。顔（鼻・両目）と両肩のvisibilityは0.6以上で、画面内にあることを要求。肩幅が小さすぎる・大きすぎる場合も受け入れない。これらの値は正答率ではない。

体モデルを2人に設定した初回検証では、映像が切り替わる際に同じ人物の重複トラックが残った。1人用の練習として1トラックに限定した。複数人が映る場面での人物分離は保証しない。

手の座標は全21点が有限、画面内、手のひらの長さが画面高の2.5〜40%という条件を満たす。体を基準にした座標で大きな手の飛び・体位置やスケールの急変を検出したらリセットする。体の位置は毎フレーム更新し、古い顔位置を使い回さない。

## 両手の検出と追跡

`numHands: 2` は以前から設定されていた。公式の `right_hands.jpg` を片手画像の直後に入れると、1フレーム目は1本、次のフレームから2本になることを再現した。Googleの公式テストはこの画像で2本を期待している。これは2本の右手を写したテスト画像なので、どちらも `Right` という結果になる。左右ラベルが同じという理由で2つの手を拒否する従来の処理は不適切だった。

左右分類を一意なIDとして扱う処理を削除し、手首・付け根の位置、短い速度予測、左右分類の補助項で2トラックを対応付ける。左右分類が同じでも位置が異なる2つの手を保持し、出力順が入れ替わってもIDを保つ。ほぼ同じ手首・中心座標の重複だけを取り除く。短い欠落用の内部トラックは最大1秒残すが、観測されない手を表示・判定へ補完しない。交差・強い遮蔽でIDを完全に保証するものではない。

画面の「手をN本検出」は現在の実検出数で、手話の正しさではない。必要本数と顔・肩の状態を別表示し、骨格を2色で描く。安定した手の形・位置・順序が揃わなければ2本映っていても進まない。WorkerのURLに版を付け、古い検出設定のキャッシュを避ける。

## 特徴と状態遷移

3D関節角度と指の長さの比から伸展・屈曲を判定する。人差し指のおじぎではPIP/DIPだけでなくMCPでの屈曲も見る。手の法線を左右に合わせ、手のひらの向きを比較する。

画像の座標はピクセルで縦横比を補正してから、両肩の中点を原点、肩幅を単位に正規化する。額は目の中央から肩幅の0.17だけ上を目安にする。個人差を含む概算であり、額への実接触までは判断できない。

| 課題       | 状態遷移と必要な特徴                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| こんにちは | 人差し指・中指を伸ばし、残りをたたんで指先を額付近へ → 両手の人差し指を胸の前に立てる → 両方の指を曲げる     |
| こんばんは | 顔の左右で両手を開き、手のひらをカメラへ → 左右の相対順序が入れ替わるまで交差 → 両手の人差し指を立てて曲げる |
| ありがとう | 片手の甲を上にして水平に構え、もう片方の開いた手を小指側から近づける → 下の手を保ったまま上の手を上げる      |

静止した最終形だけでは成功しない。形を確定するまで320msかつ3フレーム以上、交差は180ms、最終動作は240msかつ3フレーム以上を見る。表示も同じ状態機械から作り、確定したそのフレームで次の段階・お手本へ進める。「ありがとう」も片手を構える・もう片方をのせる・上げるの3段階を別々に確定する。

必要な手や顔の短い消失では現在段階を保って待ち、保持時間をゼロにする。再検出後は新たに保持時間を満たす必要がある。消失1秒以上、1秒以上のフレーム間隔、時刻の逆転・重複は最初から。各動作の制限は30秒。こんにちはとありがとうの2段階目は、元の手を見ながらもう片方の手を入れるのを待つ。

結果は一回の練習内で保持し、ことばの切り替え・もう一度・カメラ停止で消える。3段階の完了・現在・次を示し、細いバーは現在の形を保つ時間だけを示す。記録・正答確率の表示は行わない。

## 実測で確認できたこと

- 43件の合成骨格テストで、動作順序、左右反転、相対位置、追跡ID、各段階の表示、一瞬の欠落・不正値の拒否を確認。
- 公式画像4種と空画像、それぞれの反転を含む10ケースで、実モデルが動作し、静止画像をあいさつの完成として通さないことを確認。
- ブラウザではカメラ処理・状態遷移・表示・停止を確認。成功フローでは決定的な合成骨格を入力した。
- 両手の公式写真、その反転、大中小の左右2本を配置した画像、片手→両手→片手→両手、空画像の9ケースを各7フレーム入力し、最後の3フレームで期待する本数を検出。2本を再検出するまで1〜2フレームかかったケースもある。
- 公式の両手写真をcanvasの模擬カメラ映像に流し、実Worker・実モデルを通った「手を2本検出」と2色の骨格表示を確認。利用者の実カメラ・実手話の再現テストではない。

**これらは実際のあいさつ動画の認識率を示さない。** Precision、Recall、誤成功率は未測定。実映像で3つの正しい動作すべてを認識できたとの主張はしない。

## 残る限界・次の精度評価

手の重なり、横向きの手、動体ぶれ、逆光、体形、指の可動域、衣服、機器、カメラ距離で失敗する可能性がある。左右分類の揺れや、肩・目の推定のずれによる誤判定もある。深度接触、表情、口形、頭の会釈を正誤判定しない。顔や体の点を使うのは位置の基準だけ。

ろう者・手話講師に教材と模式図を確認してもらい、同意を得た複数の利用者・照明・左右・距離で収録した動作を評価する。収録時は同じ人の映像を学習用と評価用に分けず、利用者を分離する。正しい動き、順番違い、片手だけ、日常動作、無動作を混ぜて、語彙別のPrecision/Recallと誤成功回数・やり直し回数・遅延を測る。しきい値を調整したあと、未使用の評価映像で再測定する。必要なら同意・権利処理済みの時系列データで専用分類器に置き換える。
