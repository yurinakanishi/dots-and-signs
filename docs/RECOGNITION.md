# 手話の認識方法の調査と設計

調査・検証日: 2026-10-18（JST）

## 何を認識するか

日本の手話で使われる数字「1・2・3・4・5・10」の、学習課題として指定された形と動きを確認する。自由な手話動画から意味を推定する認識・翻訳とは異なる。表情や文法を含む日本手話全体を評価できるものではない。

教材を狭くすることで、単なる指の本数だけでは区別できない形（日本の「5」と開いた手など）や、静止画だけでは区別できない動き（「1」から指を曲げる「10」）を明示的に扱う。

## 一次資料

1. [Google: Hand landmarks detection guide for Web](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js)
   - 21点の画像座標・world座標・左右ラベルを取得可能。
   - 動画の検出は同期処理なのでWorkerへの分離を推奨。
   - detection / presence / tracking の閾値は、手話の正答確率ではない。
2. [Google: Gesture recognition task guide](https://developers.google.com/edge/mediapipe/solutions/vision/gesture_recognizer)
   - 組み込みの語彙は一般ジェスチャーであり、日本手話の語彙モデルではない。
   - カスタム分類器の学習が可能だが、教材ごとのラベル付きデータが必要。
3. [Zhang et al., MediaPipe Hands: On-device Real-time Hand Tracking (2020)](https://arxiv.org/abs/2006.10214)
   - 手検出とランドマーク追跡を組み合わせる端末内処理の研究。
4. [Google: Hand Landmarker tests](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/python/test/vision/hand_landmarker_test.py)
   - 実モデルの動作確認に使う公式テスト画像の出典。
5. [梅花女子大学「3Dモデルで学ぶ手話 — 数字」](https://mv.baika.ac.jp/imamura/www/suuji.html)
   - 数詞の形・動きの教材。特に5の親指の向きと10の屈曲を確認。
6. [神奈川県「指文字（数字）」](https://www.pref.kanagawa.jp/docs/dc4/cnt/f533708/p1112883.html)
   - 動画教材。数詞の学習資料としてアプリから参照可能。
7. [内閣府「手話に関する広報啓発用パネル」](https://www8.cao.go.jp/shougai/suishin/jsl/pdf/pd-6.pdf)
   - 手の動きだけでなく表情を含む言語であるという教材の範囲を確認。
8. [OpenAI: Introducing dots](https://openai.com/index/introducing-dots/)
   - 伴走するキャラクターの着想源。アプリからOpenAIサービスへの通信はない。

## 方法の比較と採用理由

| 方法                                           | 利点                                                                | 今回の課題                                                                 |
| ---------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 汎用Gesture Recognizer                         | 学習済みで導入しやすい                                              | 既存ラベルを日本手話の意味に置換できない。時系列の意味も不足               |
| 画像・動画をLLMへ送り採点                      | 文脈や説明に柔軟                                                    | 毎フレームの低遅延・決定的な再現性・PC内処理に向かない。精度測定も別途必要 |
| 専用の時系列分類器（TCN / Transformer等）      | データがあれば語彙と動きに対応できる                                | 日本手話の対象語彙、話者を分離した十分なデータ、指導者の注釈・評価が必要   |
| **手の3Dランドマーク + 幾何ルール + 状態機械** | 6課題に限定した説明可能な判定、学習データ収集前でも実装・テスト可能 | 個人差への汎化や遮蔽への限界。実測の誤受入・誤拒否を検証して調整する必要   |

現段階では最後の方式を採用。「高精度」は測定結果としては主張せず、誤受入を避ける設計目標とする。

## パイプライン

1. ユーザー操作で `getUserMedia({ audio: false, video: ... })` を開始。
2. 最大約15fps、前の推論が完了したときだけ新しい `ImageBitmap` をWorkerへ渡す。
3. 固定した `@mediapipe/tasks-vision@0.10.32` のHand Landmarkerで最大2手を検出。CPU delegate。detection / presence / tracking をそれぞれ0.7に設定。
4. 21点のworld座標から関節角度・伸展率を算出。指の絶対画面位置だけで折れ曲がりを判断しない。親指には人差し指付け根からの距離も使い、手のひらに添えた親指と伸ばした親指を区別。
5. 1手のみ、全点が画面内、十分な画面上サイズ、手のひらの法線・表裏・上向きを確認。5には親指が横向きという条件を追加。
6. 静止教材は約1.05秒、9フレーム以上の連続一致。10は開始姿勢を450ms以上、指を曲げた形を300ms以上保持。順序と手首の移動量、動きの期限を確認。
7. 形の不一致や手の消失、左右の切り替え、240ms超のフレーム欠落、逆行・重複した時刻では継続判定を破棄。
8. 成功後は結果を固定し、次のレッスン・再練習・停止で初期化。

ブラウザの鏡表示はCSSだけで行う。**推論するピクセルは反転しない。** 現行の固定モデルについて、公式pointing_up / victoryと左右反転した画像でラベルと法線の整合を確認した。旧 `mp.solutions.hands` の左右交換ルールを無条件に適用すると、このモデルでは逆になったため採用していない。バージョンを変える際は同じ検証を必ず行う。

## 確認できていること・できていないこと

確認済み:

- 合成座標による正例・誤った指・形・向き・手の消失・動きの順序の自動テスト。
- 実モデルで公式の1・2の形を検出。反転画像でも正しく受理。親指を上に向けたジェスチャーは5として受理しない。
- 公式写真を一定周期で描いた模擬カメラ映像でUIまでの統合動作。

未確認:

- 実際の利用者によるカメラの正答率・誤受入率・誤拒否率。
- 3・4・5・10の人の動画による認識率。動的な10のロジックは合成座標によるテストのみ。
- 肌の色、年齢、手の大きさ、可動域、照明、カメラ、端末性能にわたる公平な性能。
- 教材の模式図と判定条件の、ろう者・日本手話講師による監修。

指の自己遮蔽によりworld座標も推定が不安定になる。左右分類も誤ることがある。閾値の引き上げだけでは精度向上は保証できず、正しい形を受け入れにくくなる。暗さや逆光を推定する露出判定は現在実装しておらず、画面の案内で対処している。使用者ごとのキャリブレーションも未実装。

## 次の精度評価

1. ろう者・講師に教材6個と判定対象をレビューしてもらい、許容する変形を定義する。
2. 同意を得た複数の協力者から、左右の手、照明、距離、複数PCで正例と紛らわしい負例を収集する。収集機能はこのアプリに自動搭載していない。
3. 話者単位で調整用と評価用を分離する。同じ人・同じ動画のフレームを双方に混ぜない。
4. レッスンごとに成功率、誤拒否率、誤受入率、成功までの時間の中央値・95パーセンタイルを測定する。候補: 誤受入率1%未満、正しい実演の受入率90%以上を目標とし、評価前の保証値にしない。
5. 「開いた手を5」「静止した拳を10」「1→手が消失→拳を10」「動画の逆再生」「手の入れ替わり」などを必ず負例にする。
6. 評価セットは固定し、閾値変更前後を比較する。目標を満たさない教材は自動採点対象から外すか、お手本のみとして扱う。
7. 語彙を広げる場合は両手・顔・身体の座標と時間情報を持つ専用モデルへ移行する。対象言語が異なるASL等の精度を、日本手話の精度として転用しない。
